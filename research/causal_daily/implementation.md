# ETH 일일 예측 시스템 개선 결과

기준: 2026-09-05. 진단 기준 main `faf329dd8cde51f62873013e53f151cbed4ec1c4`, 배포 스냅샷 `9bef642e24a28439c853ffb09e130f79beb85554`.

## 결론

평가·표시 오류와 반복 계산을 수정했다. 30일 모델의 예측력 향상은 아직 입증되지 않았다. 새 가격·거래 흐름 후보 3개도 무변화 기준모형을 이기지 못했다. 따라서 30일 무변화 점예측을 유지하고 화면에서 기준모형임을 명시한다. 최근 급등에 맞춰 과거 예측이나 목표가를 옮기지 않는다.

GitHub 예약 시각은 최선 노력 방식이며 지연될 수 있다. 모델 코드가 main에 반영되면 호환 번들을 다시 만든다. 성공 후 일일 워크플로가 이어진다. 이미 발행한 같은 기준일 예측은 새 모델로 덮어쓰지 않는다. 다음 기준일부터 새 번들을 쓴다.

모델은 동일 저장소의 신뢰된 Actions artifact에 저장하고 작은 manifest만 `data/model-bundle` 브랜치에 둔다. 매년 모델 바이너리 수백 개를 git 이력에 쌓지 않는다. 체크섬·모델 코드·Python·scikit-learn 호환성을 검사하며, 모델 누락/불일치 또는 학습 기준일이 8일 초과하면 발행을 중단한다. artifact 보관 30일, 재학습 주 2회다. 외부 업로드 pickle을 불러오는 경로는 없다.

## 예측력·데이터 추가 효과

프로토콜을 먼저 고정하고 2025-07-01부터 목표일 2026-07-31까지 비교했다. 알려진 8월 급등에 맞춰 기간·임계값을 재조정하지 않았다. 학습창 3년, 월별 재학습, 학습 label 종료 < 테스트 첫 기준일, 동일 기준일의 가격모형/흐름 추가모형 비교다. 7일 389개, 30일 366개 기준일을 사용했다. 겹치는 기간은 독립 표본이 아니므로 최소 30일 블록 부트스트랩을 사용했다.

수치는 무변화 대비 수익률 MAE 개선율이다. 양수가 개선, 음수가 악화다.

| 후보 | 7일 | 30일 | 판단 |
|---|---:|---:|---|
| Ridge 가격 | −9.53% | −26.47% | 점예측 후보 탈락 |
| HGB 가격 | −21.48% | −29.85% | 점예측 후보 탈락 |
| HGB 가격+거래 흐름 | −23.15% | −20.65% | 점예측 후보 탈락 |

30일 흐름 추가는 같은 HGB 가격모형의 MAE를 약 7.09% 줄였다. 절대 개선은 수익률 1.368%p, 블록 95% 구간 0.281~2.507%p였다. **그러나 무변화보다 오차가 20.65% 크므로 실전 승격 근거가 아니다.** 7일 흐름 추가의 개선 구간은 0을 포함했다.

UP/FLAT/DOWN 모든 테스트 기준일의 3분류 Brier를 별도로 계산했다. 30일 Ridge는 학습 표본 클래스 비율 기준보다 약 0.49% 좋았지만 독립 전진 검증이나 통계적으로 확실한 확률 개선은 아니다. 3분류 Brier(세 항의 제곱오차 합)는 기존 사이트의 조건부 이진 Brier와 척도가 다르다.

입력 원본: 배포 스냅샷의 `lake/gold/eth_master_daily.csv`, PR #11의 `5e645555276fe3da46f682317579b39e6ab36f3b:lake/gold/lead_signal_daily.csv.gz`. SHA-256과 정확한 파라미터는 `screen/results.json`, `screen/protocol.json`에 있다. 예측 원자료 `screen/predictions.csv.gz`도 포함했다. 과거 재구성 데이터이므로 과거 공급자 수정·실제 공개시각을 완전히 복원한 실전 검증으로 부르지 않는다.

[PR #14 실행 33752623924](https://github.com/wscha231/eth-dashboard/actions/runs/33752623924) 로그도 확인했다. 짧은 구간 급등 감지 실험은 실행·자원 검증 PASS, 예측 승격 FAIL, 37.265초였다. 두 PASS/FAIL은 서로 다른 뜻이다. artifact 본문은 접근되지 않아 로그 이상으로 주장하지 않았다. #9~#14 연구 브랜치를 일괄 병합하지 않는다.

## 모델 전환과 검증의 한계

- 최초 번들은 기존 발행 모델 가족·선택 구성원·임계값을 사용한다. 7일 RF+KNN 회귀, CatBoost 방향, KNN 국면; 30일 점예측 무변화, Ridge 구간, Logistic 방향이다.
- 과거 운영의 일부 holdout/peer 가중치 상태는 저장돼 있지 않았다. 따라서 새 시간 계약과 고정 OOF 문맥을 사용하는 변환이 기존 전체 파이프라인과 완전히 같은 알고리즘이라는 주장은 하지 않는다. 저장 전후 일치 검증은 **새 번들의 직렬화·추론**에 관한 검증이다.
- OOF cutoff/hash와 모델 학습 cutoff를 구분해 저장한다. 재학습했다고 옛 OOF 평가가 새 평가가 되지 않는다.
- 기존 조건부 분류기는 큰 움직임의 방향을 학습한다. 중립을 포함한 무조건 상승 확률로 표시하지 않는다. 방향 점수와 보정 확률도 다르다.
- 저장 구간의 실전 포함률은 주간에 집계한다. 아직 검증된 80% 보장 구간으로 표시하지 않는다.
- 과거 actual 165개는 163개 정정+마감 전 2개 제외, 정정 원본 165개 보존. 기존 forecasts 값 불변, 재실행 추가 정정 0건을 확인했다.
- 회귀 검증 150개 통과. UTC/서울 표시 일치, 당일·결측 정산 차단, 원본 보존, 두 만기 원자 저장, 모델 로드 후 추론만 실행하는 경로를 포함한다.

## 재현과 운영

```bash
python -m pip install -r requirements-runtime.txt pytest
python -m pytest tests -q
# 신뢰된 배포 DB 및 공식 마스터를 복원한 뒤 최초 1회:
python scripts/train_champion.py --bootstrap
# 매일:
python scripts/predict_latest.py
python -m forecast_site.persist_forecast --summary-csv eth_forecast_outputs/latest_forecast_summary.csv --model-phase phase6_closed_daily
python -m forecast_site.backfill_actuals
python -m forecast_site.export_json
# 기존 번들 재적합:
python scripts/train_champion.py
# 누적 평가:
python scripts/review_live_forecasts.py
```

실패한 새 번들은 manifest를 발행하지 않는다. 문제 발생 시 `data/model-bundle`의 이전 호환 manifest로 되돌릴 수 있으나 8일 유효기간과 코드 호환성을 만족해야 한다. 수정된 실제값은 `actuals_revision`과 git 데이터 이력으로 추적한다. 과거 발행 예측은 수정하지 않는다.

첨부 논문에서 채택한 원칙은 rolling 검증, random-walk 비교, 로그/수익률 중심 평가, 모델 저장·추론 분리다. [Wu et al.](https://arxiv.org/abs/2405.11431v2), [Badar et al.](https://doi.org/10.3390/math13121908), [Bouteska et al.](https://doi.org/10.1016/j.irfa.2023.103055)의 다른 데이터·기간·목표에서 나온 결과를 현재 ETH 30일의 개선 증거로 사용하지 않는다.
