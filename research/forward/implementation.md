# 매일 거래 흐름 수집과 전진 예측 비교

2026-09-05. PR #15/#16의 운영 갱신·배포 수정 후 이어지는 단계다. 운영 30일 점예측은 무변화 기준모형이다. 이번 변경은 더 높은 예측력을 달성했다는 발표가 아니라, 새 데이터에서 개선 여부를 확인할 수집·발행·평가 기능의 배포다.

## 확인한 공백

- PR #11에 확보한 현물/선물 시간봉 특징은 2026-07-31에서 끝났다. 8월 이후 매일 이어서 수집하는 운영 경로가 없었다.
- 기존 수집기의 펀딩·OI·옵션 컬럼 존재만으로 과거 학습 구간이 확보되는 것은 아니다. 준비도 경고는 긴 전 기간 커버리지와 최소 180일 조건의 결과이며 모든 개별 특징이 쓸모없다는 뜻은 아니다. 옵션 snapshot의 과거 공개 시점을 만들지 않는다.
- 가격+흐름 후보는 기존 고정 평가에서 30일 가격모형보다 나았지만 무변화 기준보다 오차가 컸다. 동일 과거 급등 구간을 반복 튜닝하는 대신 발행 후 만기가 돌아오는 결과를 기록한다.

## 이번 구현

1. ETH/BTC 현물·USD-M 무기한선물 4개 1시간봉을 공식 [Binance public data](https://github.com/binance/binance-public-data)에서 증분 수집한다. checksum 확인, 정확한 UTC 24시간, 2025년 이후 현물 microseconds/선물 milliseconds 구분, OHLC·거래량·마감시각 검사를 통과한 날만 사용한다. 공식 일별 archive는 다음 날 공개되며 공개 지연이 가능하다.
2. 최대 45일 요청 창, 동시 4개, 480초 수집 예산이다. 일별 특징과 최근 시간봉 버퍼를 보관해 다음 실행에서 재사용한다. 최근 내부 결측일도 재시도한다. 401/403/451이면 새 요청을 중단한다. 다른 호스트 우회·가상 관측은 없다. 45일 이상 오래 정지했다면 더 오래된 공백은 자동 복구 범위 밖에 남고 보고서에 표시된다.
3. 17개 고정 흐름 특징을 사용한다. 일봉 종료시각과 실제 archive 다운로드 관측시각을 각각 저장한다. 기존 역사 자료의 관측시각은 미상으로 유지한다. 7일 변화는 7개 행이 아닌 7개 달력일이다. 수집 당시 검증된 특징·체크섬은 보존하고 역사 자료가 완벽한 당시 공개본이었다고 가정하지 않는다.
4. Ridge 가격 / HGB 가격 / HGB 가격+흐름 3개 후보를 7일·30일에 발행한다. 3년 학습창, 월초 기준, 학습 목표 종료 < 월초의 purge, 동일 학습 날짜, 고정 설정, 총 적합 30초 예산이다. 전체 탐색·교차검증·설명 계산은 없다. 현재 흐름 자료가 없으면 해당 후보만 보류한다. 같은 날 재시도는 아직 없는 후보만 채운다.
5. 운영 DB와 별도인 `lake/forward/forward.db`에 원래 예측을 보관한다. UNIQUE와 수정/삭제 차단 trigger로 발행값을 보존한다. 원본 특징, 소스 hash, 코드·프로토콜 hash, 학습 데이터 hash, 실제 발행시각을 함께 남긴다. 오래된 기준일로 소급 발행하지 않는다.
6. 목표 UTC 일봉이 끝나고 15분이 지나야 정확한 날짜의 실제값을 저장한다. 결측이면 평가를 기다린다. 가격 정정은 별도 revision으로 추가한다. 무변화 대비 MAE/RMSE, 학습 비율 대비 3분류 Brier를 모든 UP/FLAT/DOWN 결과에서 평가한다. 흐름 추가 효과는 기준가격과 학습 데이터 hash까지 같은 발행 쌍만 비교한다.
7. 정식 검토 후보 조건은 만기 표본 90개 이상, 겹치지 않는 30일 블록 6개 이상, MAE 개선의 블록 95% 구간 하한 > 0, RMSE·Brier 개선이다. 충족해도 운영 모델 자동 전환은 없다. 초기 몇 건의 적중을 성능 향상으로 선언하지 않는다.
8. 사이트에 `Prospective model comparison · research only`를 추가한다. 발행 당시 목표가·수익률·무조건 3분류 확률, 만기/대기 수, MAE 개선율, 수집 지연을 보여준다. 운영 카드의 조건부 방향 확률과 분모가 다르다. 과거 스크리닝과도 사건 임계값이 달라 새 프로토콜 `prospective_daily_v1`로 명명한다.

## 자동 실행·보관·배포

- 공식 일일 예측 성공 후 실행하고 매일 UTC 06:17 / 한국시간 15:17에 archive 지연 재시도를 한다. GitHub 예약 시각은 지연될 수 있다.
- 주 예측과 같은 concurrency 그룹으로 쓰기를 직렬화한다. 연구 원장·특징·manifest는 `data/forward-research`에 먼저 보관한 후 사이트의 index/forward.json만 `data/daily-forecast`에 발행한다. 공식 DB·예측 JSON을 건드리지 않으며 모델 번들 fingerprint도 변경하지 않는다.
- 이 기능의 main 반영으로 첫 실행과 배포를 자동 시작한다. 연구 데이터 파일은 실행별 artifact만 의존하지 않고 git 브랜치에 계속 보관한다. 추가 유료 API나 사람에게 보내는 알림은 없다.

검증: `python -m pytest tests -q`. 새 검사에는 archive 단위/체크섬, 누락·중복 시간 거부, 내부 결측 복구, 접근 거부 중단, 미래 데이터 영향 차단, 월초 purge, 일부 후보 보류 후 재시도, 발행값 불변, 목표일 결측/마감 전 정산 차단, 실제값 정정 이력, 중립 Brier와 최소 표본 조건을 포함한다. 최초 실행의 수집·적합 시간과 실제 사이트 반영 결과는 Actions 로그 및 `forward.json`의 원래 타이머로 확인한다.
