## 구현

- 정상 복구된 현재 월 체크포인트로 핵심 공개·독립 shadow·실패 복기를 먼저 수행한다.
- 연구 갱신·과거 검증자료·범위 seed 갱신은 그 뒤에 실행한다. 복구된 core가
  사용할 수 없을 때만 발행 전 신뢰된 연구본으로 제한된 bootstrap을 시도한다.
- 갱신은 복사본에만 적용한다. 6개 체크포인트·코드/월/학습시각·검증자료,
  원래 관측 행의 보존, 실제 원장·공개 feed 보존을 검사한 뒤 Linux의 원자적
  디렉터리 교환으로 반영한다. 실패 시 기존 상태와 갱신 마커를 유지한다.
- 기존 공개 feed가 참조하는 검증 파일을 연구본 교체 때 삭제하지 않는다.
- 선택적 실패도 실제 step outcome으로 집계하며, 핵심 공개·최종 증거 저장
  뒤 최종 상태를 실패로 표시한다. 이전 실행 성공 파일을 현재 성공으로 사용하지 않는다.
- 새 operation_health는 소형 automation_health와 기존 최종 스냅샷에 연결한다.

## 검증 기록

로컬 전체 검사 **842개 + 하위검사24개 통과**. 손상·누락 체크포인트,
다른 월/학습 코드, 미래 시각·되돌림, 아카이브 누락, 부분 쓰기 오류,
관측/원장 변조, 교환 실패와 교환 직전/직후 프로세스 종료를 검사했다.
PR의 정확한 head에 대한 CI와 병합 후 실행 결과는 PR/Issue #68의 수락
기록에서 별도로 확인한다. 이 문서 자체는 운영 성공의 증명이 아니다.

실제 보관 모델6개와 관측/원장, 공개 feed를 고정된 Git 커밋에서 읽어
**별도 로컬 복사본**을 구성했다. 모델·원본 수신 자료·관측 파티션 해시를
검증한 뒤 정상 갱신, 모델 손상, 검증 아카이브 누락 3가지 경우를 시험했다.
정상 갱신은 완료되고 실제 원장·feed의 바이트는 보존됐다. 두 오류에서는
전체 기존 파일이 그대로 유지됐다. 원본 artifact 전체를 재현한 것은 아니며
재구성본의 downloads 테이블은 비어 있다. 실제 발행이나 과거 원장에
시험 데이터를 넣지 않았다.
